06 · DEX

Glossary

Plain-language meanings of the terms on these pages.

TermMeaning
ADRArchitecture decision record: a short note of one decision, why, and what it costs. The DEX has six
agentRefA field in a settlement order holding the fingerprint of the agent request that prepared it (zero if a person placed it directly). The person signs over it
AgentGateThe DEX component that checks an agent's request and mandate and signs a receipt
Allow / escalate / blockThe three outcomes of an agent check: go ahead, ask the person first, or refuse
AMMAutomated market maker: a trading pool that prices by formula instead of an order book
AnvilA local, throwaway Ethereum-compatible test chain used for tests
Attestation (physical)A signed statement that a scanned Lumenco security feature on a physical item matches its token
Audit anchorA contract that stores the latest fingerprint of the audit log on-chain, so the log cannot be quietly rewritten
Audit log (hash chain)A list of events where each entry includes the fingerprint of the previous one; editing or deleting any entry is detectable
Autheo Agent EnvironmentThe public SolutionsAsService reference project defining agent identities, mandates, decisions and receipts
Autheo L1Autheo's own blockchain, where settlement is meant to happen; not targeted yet (local chain only)
BridgeA way to move a token's representation from one chain to another
Budget assetThe unit all of an agent's limits are counted in, e.g. a specific token in its smallest units
canTransferThe on-chain question every token movement asks the compliance module: are all checks passed?
Cash leg / asset legThe two sides of a trade: the payment and the thing bought
ClaimA property in a credential: KYC passed, accredited investor, institution
Compliance moduleThe contract that holds each asset's rules and answers canTransfer
CredentialA signed statement from a KYC provider about a wallet's claims and jurisdiction
DEXDecentralized exchange. Here: a venue where users trade from their own wallets and settlement happens on-chain
DID / did:keyDecentralized identifier: an identity that is just a public key, created locally with no registry
Delegation chainSigned permission slips from a person to an agent (and on to sub-agents), each only able to narrow what it received
Deposit tokenA test token standing in for a bank's tokenized deposits (the cash leg)
DvPDelivery versus payment: asset and cash move together in one transaction, or neither moves
EIP-712A standard for signing structured data in a wallet, so the user sees what they sign
ERC-20The common token standard on Ethereum-style chains
ERC-3643A standard for permissioned security tokens (also known as T-REX) where every transfer is checked against rules
End-to-end (e2e) testA script that runs the whole story on a fresh chain, start to finish
Exit testA test that must pass for a milestone to count as done
FoundryThe toolkit used to build and test the Solidity contracts
Fuzz testA test run with many random inputs to find edge cases
Invariant testA test that checks something always holds (e.g. total supply never changes unexpectedly) across random sequences of actions
InvocationAn agent's signed request for one specific call, carrying its delegation chain
KYCKnow your customer: identity checks done by a regulated provider
L0 MeshAutheo's planned cross-chain routing layer; mocked today
LumencoPartner producing banknote-grade micro-optic security features that can be applied to items and scanned
MandateWhat an agent may do for a person: scopes, assets, per-action limit, total budget, approval threshold
MCPModel Context Protocol: the standard way AI assistants call tools
Minor unitsThe smallest unit of an asset (like cents for dollars)
MockA stand-in with fixed answers, used until the real thing is connected
Non-custodialAutheo never holds users' keys or funds
NonceA one-time number in an order that prevents replaying it
Policy engineThe code that runs the 12 transfer checks and explains each result
Policy vectorOne test case (inputs and expected result) shared by the off-chain engine and the contract
PrincipalThe person an agent works for; the root of its delegation chain
ReceiptA signed record of an agent decision, hash-linked to the previous ones
RelayerAny account that submits already-signed orders to the chain; it cannot change them
RFQRequest for quote: asking market makers for a price instead of using a pool or book
RouterThe service that turns "this asset on that chain" into a step-by-step plan
RWAReal-world asset: bonds, funds, deposits, bullion and similar, represented as tokens
ScopeA named permission in a mandate, e.g. dex.quote or dex.order.build
STRIDEA standard way of listing threats: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege
TaaSTokenization as a Service: Autheo's issuance product; the DEX is where TaaS assets trade
THEOAutheo's network token (fees, staking); see THEO economics
TypehashThe fingerprint of an order's format; changing the format (as agentRef did) invalidates older signatures
Unsigned orderAn order prepared for a user that does nothing until the user signs it
Vendored / pinnedA dependency copied into the repository at an exact version, checked so it cannot change silently
VenueAny place a trade can happen: the Autheo DEX, an outside exchange, an AMM, a bridge
VenueAdapterThe plug-in shape every outside venue implements so the router can use it
