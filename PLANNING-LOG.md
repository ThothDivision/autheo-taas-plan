## 1. Traversal Plan

**Step 0.** Read: README, docs (Architecture, Flows, DEX integration, Compliance, Security, Interoperability, Roadmap), site build,
prior DESIGN-LOG (DADA visual run), the new development repo ThothDivision/TAAS-DEX (empty). Tools: file tools, site build,
headless Chrome (diagram render check), subagents for the panel.
**R0 premortem** (inherited plan): no operating detail (how one asset moves; what fails), no build plan or exit tests, open
questions without owners, no economics, joint-roadmap phases numbered 1–5 against roadmap phases 0–4, development repo unlinked.

**Mode: Execution** — the reader is the owner reviewing how TaaS will be built and run, then the TAAS-DEX team.
**Criterion:** buildable and testable — every milestone has an exit test a stranger could run; every decision has options, a
recommendation, an owner and a decide-by; every number sourced, computed or labelled. **Hard limits:** no claim that Autheo holds
a licence; no offer of securities; indicative economics labelled as such.
**Seed:** Kernel of Good Strategy (Rumelt) → Walking skeleton (Cockburn) → Architecture Decision Records (Nygard) → Premortem (Klein);
dotted counterpoint: Reference class forecasting (Flyvbjerg) ⇢ Shape Up (fixed time vs fixed scope).
